## 2. 每项怎么记录证据、谁来做

### 2.1 设计伙伴 0/10

- **谁来做：** 维护者（PerryLink）选人、发邀约、主持通话并记录；对方是真实的
  DSH 插件作者、重度用户或团队负责人。**不能由 agent 代发 DM 或编造受访者。**
- **怎么记：**
  - 在 [`tracker.csv`](tracker.csv) 加一行：`name` 用匿名 ID（如 `p01`）或经对方
    同意的姓名；填 `role`、`source`、`contact_date`、`call_date`。
  - 用 [`interview.md`](interview.md) 的模板记录：profile/插件、最近一次升级/
    事故、现在怎么做回归、审批路径、剪贴板/上下文丢失、时间成本、对 demo 的
    反应、是否愿意装、下一个真实任务、下一步日期、是否同意（脱敏）引用。
  - 原始笔记/录音默认私有；仓库只放**脱敏摘要**。引用前必须得到同意。
- **计数规则：** 完成 20 分钟通话才 +1；只发消息、只约时间、只收到“以后再说”
  都不算。对方拒绝也记录（`notes=declined`），然后继续下一位。
- **放哪里：** `tracker.csv` 一行 + `interview.md` 一份（或 `notes` 指向私有位置）。

### 2.2 真实安装 0/3

- **谁来做：** 外部用户在自己的机器上执行安装；维护者只做见证/收集，**不能替对方
  填“已安装”**。最好在通话里直接说：“Can I watch you install it now?”
- **怎么记：** 每条证据至少包含：
  1. 日期、匿名用户 ID、OS；
  2. `dsh --version`、`node --version`、profile 名；
  3. 实际执行的安装命令与退出码；
  4. `dsh plugin --dump-config`（或等价命令）里出现该模块的脱敏片段；
  5. 重启后仍加载的结果；
  6. 之后 14 天内真实任务的描述（不含客户数据）+ 使用日期/次数。
- **放哪里：** 脱敏日志/截图放 `docs/validation/evidence/YYYY-MM-DD-<anon>/`
  （第一次有真实证据时再建目录；不要预建空目录冒充证据），并在 `tracker.csv`
  把 `installed` / `active` 置为 `yes`、在 `notes` 写证据路径。
- **计数规则：** 装好但没真实使用 = 安装尝试，不 +1；同一人 14 天内真实使用
  ≥2 次才 +1。维护者本机 smoke、npm dry-run、demo `PASS` 都不算。

### 2.3 Check POC 0/1

- **谁来做：** 维护者谈范围/价格；买家工程负责人签范围或 LOI；买家工程师在
  自己的 CI 里跑；维护者复核结果。**没有签字/付费就不算 POC。**
- **怎么记：** 保留（私有）签字范围 / LOI 的存放位置或哈希；仓库里只放脱敏
  case note，至少包含：
  1. 买家类型（不写公司名，除非书面同意）；
  2. 3–5 个真实任务的范围与脱敏方式；
  3. 注入一个已知回归 → `dsh-check diff` exit 1；
  4. 无改动 run → exit 0；
  5. CI 运行时间 ≤15 分钟（5 个任务）；
  6. 买家工程师能自己加一个任务；
  7. 日期、DSH/Node 版本、复现命令。
- **放哪里：** 签字文件私有；脱敏记录写进 `docs/validation/check-poc-<anon>.md`
  （或合并进 STATUS 的“已发生证据”一节）。**不要伪造 LOI、报价或 CI 链接。**
- **计数规则：** 口头“有兴趣”不算；签字/付费 + 真实 CI 里拦住一次约定回归才算 1。

## 3. 什么不算证据（直接判 0）

- 维护者本机 `node scripts/test-all.mjs` / demo / npm dry-run；
- `stars`、npm downloads、views、upvotes；
- agent 自己写的“用户反馈”或模拟对话；
- “我朋友说会用”“下周一定装”但没有安装记录；
- 未脱敏的客户名、路径、token、会话内容（这类证据不收，先脱敏）。
