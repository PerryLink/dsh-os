# dsh-snip 0.2.0 真实剪贴板捕获方案

> 2026-11-20 · 基线 DSH `0.2.2-rc.4`（`ca33fd68`）· 目标：Windows 首发真读，macOS 手动，Linux 可选；零运行时依赖。
> 结论：0.2.0 做**显式捕获**（用户点按或 `snip_capture` 工具调用），不做默认后台采集。Windows 用 PowerShell helper（watch 时常驻）；macOS 只做用户点击后的 `pbpaste`；Linux 可选 one-shot。Windows 历史 API 与 macOS 后台监听留到 0.3。

## 1. 平台表与命令

| 平台 | 读当前内容 | 变化事件 | 权限/限制 | 0.2.0 |
|---|---|---|---|---|
| Windows | `Clipboard.GetContent()`；降级 `Get-Clipboard -Raw` | 无原生事件；`GetClipboardSequenceNumber` 轮询（建议 700ms） | 无系统读取授权；历史默认关；三个 opt-out 格式只是协作协议 | **P0 真读**；watch 为 P1 实验 |
| macOS | `/usr/bin/pbpaste -Prefer txt` | `NSPasteboard.changeCount` 轮询，需原生 helper | 15.4+ 程序化读取可能弹权限框；`pbpaste` 看不到 Concealed/来源 | **P0 手动**；不监听 |
| Linux | `wl-paste --no-newline --type text`；X11 用 `xclip`/`xsel` | Wayland 仅 wlroots 支持 `wl-paste --watch`；X11 只能轮询 | 无授权框；无焦点/协议不支持时可能挂起 | P1 可选 one-shot；watch 可选 |

**Windows 精确 argv**（`powershell.exe` 用 `%SystemRoot%\System32\WindowsPowerShell\v1.0\powershell.exe`，不要硬编码盘符）：

```text
powershell.exe -NoProfile -NonInteractive -ExecutionPolicy Bypass -File <pkg>/helpers/win-clipboard.ps1 -Mode once -MaxChars 65536
```

Helper 内部主路径：

```powershell
# Await: 用 System.Runtime.WindowsRuntime 的 AsTask 包装 IAsyncOperation
Add-Type -AssemblyName System.Runtime.WindowsRuntime
$null = [Windows.ApplicationModel.DataTransfer.Clipboard, Windows.ApplicationModel.DataTransfer, ContentType=WindowsRuntime]
$c = [Windows.ApplicationModel.DataTransfer.Clipboard]::GetContent()
if ($c.Contains([Windows.ApplicationModel.DataTransfer.StandardDataFormats]::Text)) {
  $text = Await ($c.GetTextAsync()) ([string])
}
```

- **WinRT 只应依赖 Windows PowerShell 5.1**：.NET 6+ 移除了内置 WinRT 投影，`pwsh` 7 不能直接这样加载 `Clipboard`（[C#/WinRT](https://learn.microsoft.com/windows/apps/develop/platform/csharp-winrt/)；本机 5.1 实测通过）。`Get-Clipboard` 可作降级：5.1 支持 `-Format FileDropList/Image`，7.4 只剩文本（[5.1](https://learn.microsoft.com/powershell/module/microsoft.powershell.management/get-clipboard?view=powershell-5.1)、[7.4](https://learn.microsoft.com/powershell/module/microsoft.powershell.management/get-clipboard?view=powershell-7.4)）。
- **序列号/标记/前台 app**：`Add-Type` P/Invoke `GetClipboardSequenceNumber()`、`RegisterClipboardFormat("ExcludeClipboardContentFromMonitorProcessing")`、`GetForegroundWindow()`；编译约 170ms，常驻后轮询开销可忽略。`sourceApp` 在“复制后已切回 DSH”时会误判，标 `sourceConfidence:unknown`，不用于安全决策。
- **历史 API**：`Clipboard.GetHistoryItemsAsync()` 可调，结果状态为 `Success` / `AccessDenied` / `ClipboardHistoryDisabled`（[API](https://learn.microsoft.com/uwp/api/windows.applicationmodel.datatransfer.clipboard.gethistoryitemsasync)、[状态枚举](https://learn.microsoft.com/uwp/api/windows.applicationmodel.datatransfer.clipboardhistoryitemsresultstatus)）。历史还要求调用方在前台，否则 `AccessDenied`（[实践](https://mzikmund.dev/blog/accessing-clipboard-history-in-uwp#retrieving-history-items)）；本机实测关闭时返回 `ClipboardHistoryDisabled`，启用后的 `Success` 路径未验证；先 `IsHistoryEnabled()` 预检。**0.2.0 不自动导入**：历史含旧秘密，绕过“只捕获本次复制”的预期；最多做 0.3 的显式按钮 + 二次确认。
- **编码实测**：5.1 stdout 默认走本地代码页（中文变 GBK，emoji 变 `??`）。helper 必须输出 **ASCII Base64 JSON**（`textB64`、`sourceAppB64` 均为 UTF-8 bytes），不要依赖 `ConvertTo-Json` 的文本编码；或显式设 `[Console]::OutputEncoding = UTF8`，但 Base64 更稳。
- **PS 脚本禁忌**：不要把 `$pid`、`$home`、`$input`、`$args` 当变量（前两者是只读自动变量，会静默失败/报错）；用 `$procId` 等名字。设 `$ProgressPreference='SilentlyContinue'`，否则 `-EncodedCommand` 会在 stderr 吐 CLIXML。

**macOS**：`pbpaste` 只读纯文本/EPS/RTF，不能只要一种类型，也没有来源/标记（[man](https://www.manpagez.com/man/1/pbpaste/)）；设 `LC_ALL=en_US.UTF-8`，用绝对路径 `/usr/bin/pbpaste`，超时 1500ms。15.4+ 的 `NSPasteboard.AccessBehavior` 可为 `.default/.ask/.alwaysAllow/.alwaysDeny`，用户发起的粘贴始终放行（[Apple](https://developer.apple.com/documentation/appkit/nspasteboard/accessbehavior-swift.enum)）。`pbpaste` 是程序化读取，**可能弹框**；无法用 pbpaste 预检权限，也不能读 `org.nspasteboard.ConcealedType/TransientType/AutoGeneratedType`（[标记规范](http://nspasteboard.org/)）。因此 0.2.0 只允许“用户点击 → 一次 pbpaste”，失败/拒绝回退文本框手动粘贴；绝不循环重试。

**Linux**：Wayland 用 `wl-paste --no-newline --type text`；`--watch` 需要合成器支持 wlroots data-control，否则会退化为弹小窗的 hack，可能挂起（[man](https://manpages.debian.org/testing/wl-clipboard/wl-paste.1.en.html)）。先用 `wl-paste --list-types` 检查 `x-kde-passwordManagerHint`；`CLIPBOARD_STATE=sensitive` 只在 `--watch` 子进程环境里出现。X11 用 `xclip -selection clipboard -o` 或 `xsel --clipboard --output`（[xclip](https://manpages.debian.org/bookworm/xclip/xclip.1.en.html)、[xsel](https://manpages.debian.org/testing/xsel/xsel.1x.en.html)），无事件，只能轮询。无 `WAYLAND_DISPLAY`/`DISPLAY` 即不可用；WSL 默认不启用（`process.platform === 'linux'`，即使能调 `powershell.exe` 也算跨机）。

## 2. DSH 宿主如何安全执行

- `ctx.shell` 是**命令字符串** seam（`bash -c` / `pwsh -Command`），由 sandbox executor 决定是否受限（[README](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/shell/shell/README.md)）。它适合模型命令，不适合固定 helper：要拼引号，且有 shell 解释面。
- `ctx.subprocess` 是**固定 argv** seam：不经 shell、显式 `cwd`/stdio/`graceMs`、限长收集、UTF-8 解码、`windowsHide: true`；子进程环境会剥掉 `*KEY*/*TOKEN*/*SECRET*/*PASSWORD*` 和 `DSH_*`（[subprocess 组 README](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/subprocess/README.md)、`packages/subprocess/subprocess-local/src/spawn.ts:122`、`src/output.ts:267`）。它**不是** sandbox，也不是任意命令执行面：只跑包内固定 helper，argv 不接受模型/用户拼接；它**不**提供超时，deadline 由调用方给。
- 插件不要硬 `inject: ['subprocess']`（0.1.x 的 composition 可能没有该 provider）；在 `read()` 时惰性 `const sp = ctx.get('subprocess')`（不要在 `apply()` 缓存 `undefined`），缺失时 `isAvailable=false`，返回 `SNIP_NO_SUBPROCESS`。
- **`spawnSync` 的约束**：① 阻塞宿主事件循环；PowerShell 单次启动 300–600ms，700ms 轮询会卡住所有会话/UI；② 绕过 `ctx.subprocess` 的环境清洗（可能把 `DEEPSEEK_API_KEY` 带给子进程）、进程树回收和输出上限；③ `shell:true` 有注入风险；④ `timeout` 只杀直接子进程；⑤ 不会自动带 `windowsHide`，默认 `maxBuffer` 1MiB，超限抛 `ENOBUFS`。仅可在 CLI/测试的 one-shot 降级里用：固定 argv、`shell:false`、`windowsHide:true`、`timeout`、`maxBuffer`、`encoding:'buffer'` 后自行 UTF-8 解码；**绝不**把剪贴板文本放进 argv。
- 推荐调用（超时/中止分离，结果只取 `collected`）：

```js
const timeout = AbortSignal.timeout(1500)
const handle = sp.spawn({
  argv: [powershell, '-NoProfile', '-NonInteractive', '-ExecutionPolicy', 'Bypass',
    '-File', helper, '-Mode', 'once', '-MaxChars', '65536'],
  cwd: homedir(), graceMs: 1000,
  signal: signal ? AbortSignal.any([signal, timeout]) : timeout,
  stdio: { stdin: 'ignore', stdout: { maxBytes: 128 * 1024 }, stderr: { maxBytes: 8 * 1024 } },
})
const outcome = await handle.done
if (signal?.aborted) throw fail('SNIP_ABORTED', 'snip: capture aborted')
if (timeout.aborted) throw fail('SNIP_CLIPBOARD_TIMEOUT', 'snip: clipboard read timed out')
if (outcome.exitCode !== 0) throw fail('SNIP_CLIPBOARD_FAILED', 'snip: clipboard helper failed')
const raw = handle.collected.stdout?.readFrom(0).text ?? ''
```

## 3. ClipboardAdapter 接口

```ts
type Snapshot =
  | { ok: true; kind: 'text'; text: string; seq?: number; sourceApp?: string
      sensitive?: boolean; reason?: string; truncated?: boolean }
  | { ok: true; kind: 'empty' | 'image' | 'file' }
  | { ok: false; code: 'UNAVAILABLE' | 'TIMEOUT' | 'DENIED' | 'BUSY'
      | 'TOO_LARGE' | 'POLICY' | 'EXCLUDED' | 'UNSUPPORTED'; reason?: string }

interface ClipboardAdapter {
  readonly platform: 'win32' | 'darwin' | 'linux'
  isAvailable(): Promise<boolean>
  read(opts?: { signal?: AbortSignal; timeoutMs?: number }): Promise<Snapshot>
  watch?(onChange: (s: Snapshot) => void,
         opts?: { signal?: AbortSignal; intervalMs?: number }): Promise<() => Promise<void>>
}
```

- 映射：`win32 → Win32ClipboardAdapter`（WinRT 优先，`Get-Clipboard` 降级）；`darwin → PbpasteAdapter`（仅手动）；`linux → WlPasteAdapter`/`XclipAdapter`（按环境二选一）。
- `isAvailable()` 只做能力探测：win32 检查 `powershell.exe` 存在；darwin 检查 `/usr/bin/pbpaste`；linux 检查 `WAYLAND_DISPLAY`+`wl-paste` 或 `DISPLAY`+`xclip`/`xsel`。不要用 `spawnSync('which')`。
- **轮询 vs 事件**：Windows 无消息循环就没有 `WM_CLIPBOARDUPDATE`，用 seq 轮询；macOS 用 `changeCount` 轮询（需原生，0.3）；Linux Wayland 可 `--watch`，X11 只能轮询。所有 `read()` 都必须有超时和 `terminate()` 兜底；轮询只保证最终态，连续两次复制可能只捕获后一条。
- **watch 生命周期**：helper 退出→指数退避重启（上限 30s）；dispose→abort→terminate→await `waitForExit()`；回调异常只记错误码，不中断循环。
- 0.2.0 只注册内部 adapter；`ctx.clipboard` seam 暂不注册（避免与未来官方冲突），先暴露 `ctx.snip.capture()` / `snip_capture`。

## 4. 安全

- **默认关**：`capture.enabled=false`；安装不采集，显式开启 + 一页说明；`snip_capture` 不能绕过该开关（Agent 调用还需一次确认/Grant）。远程访问 Web 时 host 剪贴板是服务器的，只允许浏览器手势读取，不跑 host adapter。
- **先标记后内容**：Windows 读 `ExcludeClipboardContentFromMonitorProcessing`（存在即排除）和 `CanIncludeInClipboardHistory`（DWORD 0 排除；`CanUploadToCloudClipboard=0` 只关云同步，不单独排除）；macOS 的 Concealed/Transient/AutoGenerated 只能由 0.3 原生 helper 读取，0.2.0 的 pbpaste 读不到，所以 macOS 不自动采集；Linux Wayland 先查 `x-kde-passwordManagerHint`。三个 Windows 格式是协作协议，不是强制（[Microsoft](https://learn.microsoft.com/windows/win32/dataxchg/clipboard-formats)）。
- **再内容检测**：复用 `packages/snip/index.js` 的 `detectSecret()`；自动捕获命中时不调用 `add()`，只计数“跳过 1 条可疑内容”，不显示内容。显式 `snip_add` 保留现有 `[redacted:<reason>]` 语义。
- **不写原文日志**：不 `ctx.logger.*` 文本、不把 helper stdout/stderr 原样抛错、不把文本放 `sourceApp`；helper 只回 `textB64`/`sourceAppB64` + 长度/哈希/错误码。工具结果默认只返回 `{handle, kind, bytes, redacted}`，**不返回原文**（工具结果会进 append-only 会话日志）。
- **TTL/上限**：捕获默认 24h，可配到 7d；秘密强制 1h；`maxEntries` 200（Pro 500）、单条 64 KiB；`pause()` 停止读取并丢弃在途结果，`clear()` 清空；过期在访问时 + 定时清扫。
- **权限提示**：macOS 15.4+ 首次读取可能弹框；UI 先解释，拒绝/超时回退手动，不自动重试。Windows/Linux 无系统读取授权。
- **图片/文件**：0.2.0 只识别并返回 `image/file`，不读内容、不入库；避免图片里的秘密与体积问题。

## 5. 测试

- **可注入 runner**：`createAdapter({ platform, run })`；默认 `run` 走 `ctx.subprocess`，测试传 fake，不触摸真实剪贴板。若保留 `spawnSync` 降级，单测用 `node:test` 的 `mock.method(child_process, 'spawnSync')` 覆盖一次即可。
- **fixture**：`text.txt`（CJK+emoji+CRLF）、`empty.txt`、`image.png`（只做格式标记）、`secret.txt`（`sk-...` 合成串）、`oversize.txt`；断言逐字解码、`EMPTY`、`UNSUPPORTED`、`EXCLUDED`、`TOO_LARGE`。
- **契约用例**：`isAvailable` 在工具缺失时为 false；`read` 的 argv 精确、无 shell、有超时；stdout base64 解码；`done` 拒绝/超时/SIGTERM 映射到稳定错误码；`watch` 只在 seq 变化时回调、重复 seq 去重、dispose 后不再回调；TTL 到期、`pause()` 后不读、`clear()` 后无残留。
- **真实 smoke**：`test/smoke/*.test.js` 用 `test.skipIf` 默认跳过，只有 `SNIP_SMOKE=1` 且平台匹配才跑；Windows 调 `powershell.exe`，macOS 调 `pbpaste`，Linux 按工具存在性；只断言“可读/长度≥0/不打印内容”，不落盘真实剪贴板。
- **打包**：`npm pack` 必须包含 `helpers/win-clipboard.ps1`；`files` 加 `helpers/`；做一次 tarball 解包 smoke，防止 helper 漏发。

## 6. 0.2.0 范围与步骤

| 能力 | Windows | macOS | Linux |
|---|---|---|---|
| 当前文本 `read()` | ✅ P0（WinRT/Get-Clipboard） | ✅ P0（点击后 pbpaste） | ✅ P1（工具存在时） |
| 后台 `watch()` | ⚠️ P1 实验（常驻 helper + seq 轮询） | ❌ 0.3（原生 changeCount） | ⚠️ 仅 wlroots `--watch`，P2 |
| 历史导入 | ❌ 0.3 显式按钮 | — | — |
| 图片/文件 | ❌ 只识别不读 | ❌ | ❌ |

若排期只够 P0：三平台都只提供 `read()`，`watch()` 返回 `UNSUPPORTED`；**不要**把半成品后台监听默认打开。

1. 新建 `packages/snip/lib/clipboard.js` + `lib/adapters/{win32,darwin,linux}.js`；保持 `index.js` 可独立导入，不新增依赖。
2. 写 `packages/snip/helpers/win-clipboard.ps1`：`-Mode once|watch`、`-MaxChars`、Base64 JSON、P/Invoke seq/标记/前台 app、WinRT 失败降级 `Get-Clipboard -Raw`。
3. `SnipService` 增加 `capture()` / `status()` / `pause()` / `resume()`；`capture()` 内部先过标记与 `detectSecret`，再走现有 `add()` 持久化；给 `add()` 加可选 `ttlMs`（秘密 1h、普通默认 24h、上限 7d）。
4. 注册 `snip_capture`（显式）与 `snip_status`；**不要**在 `apply()` 里自动读剪贴板。
5. 配置：`capture: { enabled:false, watch:false, intervalMs:700, timeoutMs:1500, maxChars:65536 }`；`enabled` 默认 false。
6. 面板/CLI 加“捕获当前剪贴板”“暂停/清空”；macOS 失败时显示手动文本框。
7. 单测 + smoke + `npm pack` 检查；Windows 真机跑 100 次复制（文本/多行/CJK/emoji/空/图片），断言不丢不重、无原文日志。
8. 更新 `CHANGELOG.md`/README/`package.json` 到 0.2.0；发布前确认 helper 在 Windows 10/11 的 5.1 与 pwsh 7 环境都走对分支。
